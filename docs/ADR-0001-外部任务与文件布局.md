# ADR-0001：外部任务、文件布局与实现偏差

- 状态：已采纳
- 日期：2026-11-04

## 背景

开发计划 v2.1 描述了导入、克隆、导出与外部批量导入的完整链路，但部分细节需要在本仓库落地时定稿。
本文记录实现阶段做出的决定与理由，便于后续评审与回溯。

## 决策

### 1. 模块划分

`domain`（纯逻辑，无 Spring）→ `core`（Spring 服务、SQL、外部调用）→ `web`（控制器、页面）。

- 好处：序列对齐、表头检测、ID 生成、CSV 写出可以纯 JUnit 测试；Spring 上下文只在集成测试中启动。
- 代价：`core` 中的 `CaseJsonCodec` 之类需要 Jackson；`domain` 只用 POJOs/records。

### 2. Flyway 通过 `spring-boot-starter-flyway` 引入

Boot 4 把 Flyway 自动配置拆到独立模块；仅依赖 `flyway-core` 时应用能启动但**不会建表**（表现为
`Table "APP_SETTING" not found`）。因此改用 starter。这与计划 §6.1 的依赖清单不同，已记录在 README。

### 3. H2 URL 不带 `AUTO_SERVER`

H2 2.4 拒绝 `AUTO_SERVER=TRUE` 与 `DB_CLOSE_ON_EXIT=FALSE` 的组合（`Feature not supported`）。
本系统一个实例独占一个库，不需要多进程访问，直接使用 `jdbc:h2:file:{dir}/db/otc`。

### 4. 数据目录在上下文启动前解析

H2 的 JDBC URL 由数据目录推导，因此数据目录不能只写在 `application.yml`。
取值顺序：`-Dapp.data-root` → `APP_DATA_ROOT` → `./data`；租户目录为 `{root}/tenants/{tenant}`。

### 5. 金额精度

`data_json` 中的小数按 `BigDecimal` 存储与读取（`spring.jackson.deserialization.use-big-decimal-for-floats`），
导出时 `toPlainString()` 保留源精度（`1500000.00` 不会变成 `1500000`）。
Business Record Id 的规范化则去掉尾随零，保证 `1.50` 与 `1.5` 视为同一值。

### 6. 外部产出的隔离

- `test_case.origin = EXTERNAL_OUTPUT`；
- `/api/batches` 默认过滤 `kind=EXTERNAL_OUTPUT`，只有 `includeExternal=true` 才返回；
- 产出浏览使用独立的 `/outputs` 与 `external_output` 表，删除产出会级联删除其批次与用例；
- 扫描幂等：以文件 `sha256` 去重。

### 7. 导入是同步事务

提交时在请求线程内完成“读取 → 转换 → 入库”，任务状态仍按 `PENDING → RUNNING → 终态` 记录，
便于后续改为异步执行（例如把 `ImportService.commit` 投递到单线程执行器）而不改表结构。
单个 sheet 失败不会回滚其它 sheet：失败计入 `PARTIAL` 并写入问题明细。

### 8. 列分配与重名

交易块边界是确定性的：严格模式恒为“起始列 + 业务字段数”，非严格模式为“起始列 ~ 最后一个列名命中业务字段的列”。
列名匹配只接受“去首尾空格 + 忽略大小写后相等”，不做相似度猜测；非严格模式下重名列视为定义/文件错误，
严格模式下按位置区分。导出始终按产品定义顺序输出，重名列保持原样（外部工具按位置读取）。

### 9. 前端形态

Thymeleaf 页面壳 + 原生 ES Module，无 npm 构建；配色/布局复刻参考项目
`ccp-report-validation-result-viewer`（顶栏渐变、卡片、胶囊选项卡、粘性表头、多主题）。

## 后果

- 需要业务确认的仍是计划附录 D 的 Q1–Q8（外部接口字段、真实字段清单、公式规范化、管理列导出范围等）。
- 若后续切换 PostgreSQL：只改 `spring.datasource.url` 与驱动，SQL 已避免 H2 专有语法（除 `DATEDIFF`，仅用于任务排序）。
