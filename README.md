# Tabular 结构化文本数据管理工具

HKEX OTC Clear 清算测试数据（Markitwire ATRS）的用例导入、管理、克隆与 CSV 导出工具。
界面标题为「Tabular 结构化文本数据管理工具」，取自 `messages*.properties` 的 `app.title`（顶栏与浏览器标题共用）。

实现依据：OTC Clear 测试数据导入管理平台开发计划 v2.1（随任务提供的 `docs/开发计划.md`，位于独立的需求文档目录，不在本仓库内）。本仓库是该计划的落地实现。

相关文档：[REST 接口](./docs/REST接口.md)、[CSV 格式](./docs/CSV格式说明.md)、
[ADR-0001](./docs/ADR-0001-外部任务与文件布局.md)、[验收清单](./docs/验收清单.md)。

## 启动

### 单机模式

```bash
gradle :otc-clear-web:bootJar
java -Dapp.data-root=./data -jar otc-clear-web/build/libs/otc-clear-testdata.jar --no-tenant --server.port=8080
```

### 多租户模式（一个实例绑定一个租户）

```bash
java -Dapp.data-root=./data -jar otc-clear-web/build/libs/otc-clear-testdata.jar --tenant --tenant-id=hkex-otc --server.port=8080
```

| 参数 | 行为 |
| --- | --- |
| `--tenant` + `--tenant-id=xxx` | `app.mode=TENANT`，租户 id 需匹配 `[a-z0-9-]{1,32}`（也接受 `--tenant-id xxx` 写法） |
| `--tenant` 缺 `--tenant-id` | 启动失败并给出原因 |
| `--no-tenant` | `app.mode=SINGLE`，租户固定 `default` |
| 两者同时 | 启动失败 |
| 都不传 | 默认 `SINGLE`，租户 `default` |
| `--init-database` | 启动前**擦除**该租户的数据并重建为出厂状态（见下） |
| `--help` / `-h` | 打印命令行帮助并退出，**不启动服务** |

数据目录优先级：`-Dapp.data-root=...` > 环境变量 `APP_DATA_ROOT` > `./data`（启动时会打印 `Data root: <解析后的绝对路径>`）。
（数据目录必须在上下文启动前确定，因为 H2 的 JDBC URL 由它推导；因此不通过 `application.yml` 调整。）

数据目录支持以下写法（`-Dapp.data-root` 与 `APP_DATA_ROOT` 同样适用）：

| 写法 | 示例 | 说明 |
| --- | --- | --- |
| Windows 绝对路径 | `C:\otc-data` / `E:/otc-data` | 原样使用 |
| 类 Unix 绝对路径 | `/srv/otc-data`；Windows 上的 MSYS 写法 `/c/otc-data` | MSYS 写法会映射为 `C:\otc-data` |
| 相对路径 | `./data`、`mydata/otc` | 相对**当前工作目录**解析 |
| `classpath:` | `classpath:data` | 解析到 classpath 根（`application.yml` 所在目录），供 IDE 源码模式使用；打包成 jar 后不可写，会报错提示改用 `projectdir:` |
| `projectdir:` | `projectdir:data` | IDE 源码模式 = 项目根目录（向上找 `settings.gradle` / `.git`）；jar 模式 = **jar 包所在目录** |

值可以带引号（`APP_DATA_ROOT="C:\otc-data"`），只有空值才会退回默认 `./data`。

解析出的 `app.mode` / `app.tenant.id` / `app.data-root` 与 `spring.datasource.url` 以**最高优先级属性源**注入（`StartupPropertyOverrides`），
`application.yml` 有意不再声明这些键：Spring Boot 的默认属性优先级最低，写进配置文件反而会把启动参数盖掉（曾导致租户实例显示「单机模式」）。

### 数据初始化 `--init-database`

用于把某个租户重置为「出厂状态」（典型场景：交付前清空演示数据、环境重建）：

```bash
java -Dapp.data-root=./data -jar otc-clear-web/build/libs/otc-clear-testdata.jar --tenant --tenant-id=hkex-otc --init-database
# 或
run-tenant-prod.cmd hkex-otc 8080 --init-database
```

执行过程（全部发生在 Spring 上下文创建之前，因为数据库文件由数据源打开）：

1. 解析模式与租户后，列出将删除的内容：`<dataRoot>/tenants/<租户ID>/` 下的 `db`、`uploads`、`batches`、`exports`、`jobs`
   五个目录（含文件数与字节数）；**只影响这一个租户目录**，其他租户与目录内的其他文件不动；
2. 检查数据库是否被占用：`db/otc.mv.db` 存在独占文件锁（即还有实例在跑）时**直接拒绝**，不删除任何文件，退出码 1；
3. 交互确认：必须输入 `YES`（大小写不敏感）才会删除；其他输入视为取消，**不删除任何文件**，退出码 2；
4. 删除成功后**继续启动服务**：Flyway 在空库上重建表结构，`ProductDefinitionSeeder` 重新写入出厂数据——
   内置类型集合与其取值（`VALUE_TYPE` / `FIELD_ROLE` / `FIELD_TAG` / `CONV_METHOD` 示例）、平台与基产品模板
   （`MW/IRS`、`MW/OIS`、`MW/CCSIRS`、`CFETS/*`）以及示例产品（`IRS` / `IRS_SIMPLE` / `IRS_DUP_DRAFT` / `OIS`）；业务数据（任务、批次、用例、
   导出记录、外部任务、审计、上传与基线文件）全部为空。

首次初始化（目录不存在或本就没有数据）同样可用该选项：提示「already empty」，随后照常建库并写入上述出厂数据。

退出码：`0` 正常启动（含初始化成功）、`1` 被占用或删除失败、`2` 用户取消初始化。

Windows 下可直接双击仓库根目录的启动脚本：

| 脚本 | profile | 参数 | 说明 |
| --- | --- | --- | --- |
| `run-single.cmd` | dev（默认） | `[端口] [--init-database \| --help]` | 单机模式，租户 `default`，端口 8080 |
| `run-tenant.cmd` | dev（默认） | `[租户ID] [端口] [--init-database \| --help]` | 多租户模式，默认 `default` / 8080 |
| `run-single-prod.cmd` | **prod** | `[端口] [--init-database \| --help]` | 单机模式，默认端口 8080 |
| `run-tenant-prod.cmd` | **prod** | `[租户ID] [端口] [--init-database \| --help]` | 多租户模式，默认 `default` / 8080 |

脚本把以 `-` 开头的参数原样透传给程序（`--init-database` 需在提示后输入 `YES`，`--help` 打印帮助后直接退出），
其余位置参数依次是租户 ID 与端口，因此顺序无关紧要：`run-tenant-prod.cmd --help` 与 `run-tenant-prod.cmd hkex-otc 8080 --init-database` 都可用。

`*-prod.cmd` 等价于给 `java` 追加 `-Dspring.profiles.active=prod`（模板缓存开启、审计入口关闭、堆内存与磁盘指标隐藏）。
数据目录仍由环境变量 `APP_DATA_ROOT` 决定（默认 `%~dp0data`），例如：
`set APP_DATA_ROOT=E:\otc-data && run-tenant-prod.cmd hkex-otc 8081`。

### 配置档（dev / prod）

| 文件 | 用途 | 主要差异 |
| --- | --- | --- |
| `application.yml` | 公共配置 | 端口、限流、导入/导出默认值、Flyway、日志级别；`spring.profiles.default: dev` |
| `application-dev.yml` | **默认**：开发与测试 | Thymeleaf 不缓存、health 详情全开、连接池 8、`app.audit.enabled: true`、`app.resources.heap-metrics-enabled: true` + `disk-metrics-enabled: true` |
| `application-prod.yml` | 生产 | Thymeleaf 缓存开启、health 详情关闭、连接池 24、`app.audit.enabled: false`、`app.resources.heap-metrics-enabled: false` + `disk-metrics-enabled: false` |

不指定 profile 时使用 `dev`；需要切换到生产配置时显式指定，或用上表的 `*-prod.cmd` 脚本：

```bash
java -Dspring.profiles.active=prod -Dapp.data-root=./data -jar otc-clear-web/build/libs/otc-clear-testdata.jar --tenant --tenant-id=hkex-otc
```

`app.audit.enabled=false`（prod 默认）时不写审计记录，导航不显示「审计日志」，`/audit` 与 `/api/audit` 均返回 404，
「关于」页面也不再出现任何与审计相关的文案或入口。

`app.resources.heap-metrics-enabled` / `app.resources.disk-metrics-enabled`（prod 默认关闭）控制【资源统计】里的
堆内存（含非堆内存）与磁盘空间数据：关闭后后端不再读取这些指标（接口返回 0，`metrics` 标记为 `false`），
页面对应的卡片与行整块隐藏，其余租户级统计不受影响。

`app.ui.show-tenant`（默认 `false`）控制是否在界面上显示租户标识：关闭时顶栏不渲染「租户 xxx」徽标、
「关于」页面不列出「租户」一行（`GET /api/context` 的 `showTenant` 同步为 `false`），
【资源统计】也不再显示租户 ID，其路径与数据库 URL 里的租户目录段统一脱敏为 `tenants/***`。
单租户部署无需暴露租户信息，需要多租户对照时再用 `--app.ui.show-tenant=true` 打开。

`app.ui.issue-preview-rows`（默认 `5`）与 `app.ui.issue-inline-limit`（默认 `10`）控制**所有问题清单**的折叠显示
（导入预览问题区、导入结果、多 Sheet 预检的阻断 / 警告清单、任务详情的问题明细共用同一套实现：
`static/js/issue-list.js`）：清单先渲染前 `issue-preview-rows` 条，其余折叠成「更多…（还有 N 条）」；
总条数不超过 `issue-inline-limit` 时就地展开，超过则打开右侧抽屉按每页 20 条分页查看。
`issue-inline-limit` 支持**租户级覆盖**：导入向导问题区里的「问题清单展开上限」直接修改，
经 `PUT /api/settings/ui` 持久化（取值夹在 5–200），并由 `GET /api/context` 的 `ui` 下发；未设置时用配置文件的值。

## 审计范围

当前只对 **产品定义**（`BASE_PRODUCT` / `BASE_FIELD` / `PRODUCT` / `PRODUCT_FIELD`）与 **元数据**（`META_SET` / `META_ITEM`）
的改动写审计；任务、批次、用例、导出、外部任务、克隆等模块不再写审计。审计记录按功能模块（`module`）、审计对象（`entity_type`）、
动作（`action`）分类，历史记录在迁移 `V8__audit_module.sql` 中按实体回填模块代码。

| 导入向导 | `/import` | 上传 → 参数化预览（400ms 防抖）→ 提交；可选「任务名称 / 任务 ID」：填已有任务名或 ID 则批次并入该任务，填写新名称则用它建任务；未选择产品时只做原始数据预览（不套用设置项、不可提交），选择产品后按定义校验；表头行、定义起始列、数据起始/结束行可调；预览表按交易字段 / 管理列 / 未映射列分色，**底部翻页条**（首页 / 上页 / 下页 / 末页，每页 20 / 50 / 100 / 200 行，显示「第 A–B 行 / 共 N 行」）可浏览整份文件而不必一次读入，公式单元格带 `ƒ` 标记；左侧 Sheet 列表每项带复选框，可多选后点「导入所选 Sheet」一次导入（先逐个校验：阻断型错误拒绝整批、警告型列清单二次确认），也可点「全选」；**字段值校验失败**的单元格按严重级别标色（警告标黄、错误标红）并悬停显示原因，错误级会拒绝该行；「导入选项」控制管理列与未映射列是否落库，「空行前停止」「错误行前停止」控制扫描终止条件；状态标签可点击折叠问题区；结果面板与预览面板同宽，成功/失败分别展示，且不重复预览阶段已展示的列映射提示；**问题清单默认只显示前 5 条**，第 6 行是「更多…（还有 N 条）」：总条数不超过「问题清单展开上限」时就地展开，超过则打开独立抽屉分页查看（每页 20 条）；预检弹窗的阻断 / 警告清单与结果面板同一套规则 |

## 多语言

支持三种语言：`zh-CN`（简体中文，默认）、`zh-HK`（简体中文（香港））、`en`（英语）。顶栏下拉切换，
选择写入 `lang` Cookie；也可用 `?lang=xx` 临时切换。

- 服务端：`otc-clear-web/src/main/resources/i18n/messages*.properties`，Thymeleaf 用 `#{key}` 渲染页面标题与静态文案；
- 前端：`GET /api/i18n` 返回同一套字典，`ui.t(key, ...args)` 取词，`data-i18n` / `data-i18n-title` / `data-i18n-placeholder` 自动套用；
- 当前覆盖全站外壳与「产品定义」「元数据」页面；其余页面保留中文，新增文案时在三个 properties 中补同一个 key 即可逐步迁移；
- 元信息里的枚举取值名称（如「文本」「关键字段」）属于用户维护的数据，不参与界面翻译。

## 产品定义模型

产品定义完全由数据库驱动，页面上的改动立即对导入、导出、克隆生效。

```
平台（固定枚举 MW / CFETS）
└── 基产品（代码自由填写、按平台各自维护，数量不限；IRS / OIS 等仅为出厂种子与输入建议）
    └── 产品（代码全局唯一）
```

- **基产品**持有该平台下的完整字段集合；不同平台的同名基产品互不影响。代码不再与平台预设绑定：MW 与 CFETS 都可继续新增任意基产品（例如 CFETS 的 NB_IRS），同一平台内代码唯一、数量不限。
- **用 CSV 快速起字段**：新增基产品时可拖入或选择 CSV，读取首行表头批量生成字段（文本 / 业务字段 / 必填），随后再通过字段管理完善类型、标签与序号（对话框内提示「使用文件快速导入字段后须通过字段管理功能继续完成基产品定义」）。
- **快速字段（已有基产品）**：字段表头「新增字段」右侧的【快速字段】按钮可选择一个 CSV 文件，用其首行列名批量生成字段
  （列名即列名，值类型 `TEXT`、角色 `BUSINESS`、必填，序号从当前最大序号续排；已存在的列名自动跳过），
  一次完成后提示新增数量（`POST /api/catalog/base-products/{id}/fields/from-csv`）。
- **产品**从基产品派生字段副本（`base_field_id` 溯源），一律继承全部字段，创建后只能做减法与微调：
  - 可删除字段；可调序号、标签、备注；管理字段可选必填或选填；
  - **所有业务字段在派生产品中恒为必填**，首次继承与「同步基产品字段」时自动置为必填，编辑页也只读展示；
  - 产品拥有**独立序号**（恒为 1..N），可自由拖动排序，基产品序号仅作为「父序号」展示；
  - 身份属性（列名、别名、值类型、角色、格式、克隆模板、业务键标记）随基产品变更自动传播。
- **严格模式**：派生产品可开启「严格模式」。开启后导入的**定义区**（从「定义起始列号」开始）必须与产品的
  全部字段（业务字段 + 管理字段）**顺序、数量与列名完全一致**，多余的列一律归为**未映射列**；
  不一致时预览报 `STRICT_ORDER_MISMATCH`（区内出现产品未定义的列时报 `TRADE_BLOCK_NOT_CONTIGUOUS`）、导入直接失败。
  关闭时：业务字段按**列名**匹配（从定义起始列号开始）、管理字段按**列名**在整个表头匹配，其余列归为未映射列。
  非严格模式下产品字段的列名必须唯一，否则该产品**定义无效**、无法导入。
- **定义有效性**：非严格模式下存在重复列名的产品在派生产品列表与详情面板标记「无效」（红色），字段表内重复行
  由警告型黄色高亮改为错误型红色高亮并给出说明条；导入向导的产品下拉会标注「（无效）」并禁用提交。
  严格模式下重复列名仍只是警告型高亮。
- **同步**：基产品新增字段不会自动出现在已有产品中，需在产品上执行「同步基产品字段」（可选是否补齐缺失字段）；
  基产品删除字段会级联删除产品中的副本。
- **删除**：产品与基产品均为硬删；产品被**有效**批次或用例引用、基产品仍有产品时返回 `409`（已删除的批次与用例不再计入占用）。
- **元数据**：值类型、角色类型、标签全部来自 `/meta` 维护的枚举集合。值类型可以引用另一个集合
  （例如 `CONV_METHOD` → `Modified Following / Flowing / Preceding`），此时该字段成为枚举字段，导入时按被引用集合校验。
  业务处理依赖的**必须取值**为值类型 `TEXT` / `INTEGER` / `DECIMAL` / `DATE` / `TIME` / `DATETIME` / `BOOLEAN`
  与角色 `BUSINESS` / `MANAGED`：列表中带「必须」标记、不可编辑或删除（服务端返回 `409`），
  每次启动还会补齐缺失的必须取值，保证字典始终完整。`CONV_METHOD` 只是出厂示例枚举引用类型，可按普通类型改名或删除。
- **字段值校验**：字段可以绑定一个校验规则表达式（见下文「字段值校验规则」），派生产品继承并可覆盖；
  规则的**严重级别**决定它是否阻断导入（警告仅提示、错误拒绝该行）。
- **角色类型**：`BUSINESS`（业务字段，参与交易块映射与必填校验）、`MANAGED`（管理字段，只有声明过的管理字段
  才会在导入时被识别为管理列，可选或必填）。业务键（Trade ID 一类的唯一标识列）由内部的 `key_flag` 标记维护，
  不再作为独立角色展示。
- **序号唯一**：新增或编辑字段时序号不能与其他字段重复，前端即时提示「序号 n 已被其他字段占用」，服务端返回 `409`。
- **预置模板**：`MW / IRS` 27 个字段（`_TestCaseId`、`_Remarks` + 25 个业务字段，交易块首列为必填的
  `Report Timestamp`，含重名的两个 `Rate`，默认严格模式）、
  `MW / OIS` 22 个字段（`_TestCaseId`、`_Remarks` + 20 个业务字段）、`MW / CCSIRS` 70 个字段（4 个管理字段
  `_TestCaseId`、`_Remarks`、`Scenario Group`、`Priority` + 66 个业务字段，其中前 50 个为必填）；
  另有 `IRS_DUP_DRAFT` 保留重名列且非严格，用于验证「无效」状态。派生产品从这些字段派生后按需删减。
- **字段列表**只展示业务维度：序号、列名、值类型、角色类型、标签、必填、备注；显示名、内部 Key、别名仅在字段编辑器内部保留。

### 产品定义页交互

- **紧凑表格**：产品定义与元信息页使用行高更小的密集表格，操作列改为图标按钮（编辑 / 删除 / 新增 / 锁定），序号等数字列居中。
- **列表操作图标化**：各列表（任务、批次、用例、导出记录、产出、导入结果）的「操作」列统一为图标按钮——眼睛（查看 / 详情 / 纵向查看）、图层（打开批次）、下载、垃圾桶（删除），均带悬停提示与无障碍名称。

- **字段级筛选与排序**：字段搜索框按列名、别名、值类型、角色、标签、备注过滤；值类型 / 角色 / 标签下拉与「仅必填」可叠加，筛选条件以 chip 展示并可单条移除或一键清除。点击表头在「升序 → 降序 → 原始顺序」之间循环，排序状态仅由表头箭头表示。
- **拖动排序**：解锁且无筛选 / 排序时，可点击选中行并拖动到目标位置；基产品与派生产品各写自己的序号（产品序号恒为 1..N），互不影响。
- **重复列提醒**：列名按不区分大小写比较，重复时行底色使用与高亮同色（`--mark-bg`）、列名左侧加警示条并显示「重复列」徽标，表格上方汇总提示「检测到重复列」；仅为警告，不阻止编辑。
- **派生产品字段表**：第一列为产品自身序号，第二列为「父序号」（对应基产品字段序号）；同样支持筛选、排序、锁定与拖动排序，且字段集始终是基产品字段的子集。
- **新增产品**：只需填写产品代码、名称与说明，创建后继承基产品全部字段；面板底部以独立提示块展示「新增后请进入产品详情页继续完成产品定义」。
- **产品详情面板**：标题下方以副标题展示「字段 n · 用例 n」；继承说明文字所在行右侧放置锁定与同步按钮。
- **严格模式开关**：衍生产品列表在操作列前提供「严格模式」滑动开关，默认关闭；编辑对话框同样可以切换。
- **基产品标题**：面板标题行显示「平台 · 基产品 · 名称」，下方以说明性小字展示基产品描述（无描述时自动隐藏）；字段数 / 产品数只在左侧列表展示。
- **标签直选**：字段编辑面板的标签不再使用复选框，改为可直接点选的标签按钮，选中值以主题强调色实心标签展示。
- **长文本备注**：备注支持多行输入与换行保留；超过阈值的备注以省略号展示，点击弹出可自由拉伸的浮层面板（`resize: both`），面板右上角为复制图标，支持一键复制。

## 定义备份与还原（导出 / 导入）

【产品定义】与【元数据】页面头部各有三个按钮：**导出 SQL**、**导出 Excel**、**导入**，用于整份定义的备份与还原。

范围：
- 产品定义 = `PLATFORM` + `BASE_PRODUCT` + `BASE_FIELD` + `PRODUCT` + `PRODUCT_FIELD`（平台为全局共享，还原时按 code 合并，不删除其他租户也在用的平台）；
- 元数据 = `META_SET` + `META_ITEM`（含集合类型、校验规则类型与严重级别）。

导出：
- **Excel**（`.xlsx`）：每个表一个 sheet，首行是列名（`code` / `platform_code` / `field_key` 等，与库列同名），一个 sheet 一行一条定义；这是**可再次导入**的格式，可直接用 Excel 编辑后再导入；
- **SQL**（`.sql`）：注释头（范围、租户、生成时间）+ 事务 + 按依赖顺序的 `DELETE`（限当前租户）+ `INSERT`（保留原 ID 与时间戳；平台用 `MERGE` 以便重放），可直接用 H2 客户端对租户库重放，实现整库还原；SQL 仅用于备份/迁移，**不作为导入格式**；
- 两者都直接下载（`product-definitions-<租户>-<时间>.xlsx` / `meta-dictionary-<租户>-<时间>.sql`）。

导入（仅 `.xlsx`）分两步：
1. **预检**（不写库）：上传后逐行分类并在独立抽屉面板展示——
   - **新增**：库中没有该业务键；
   - **冲突**：同业务键已存在但可写字段内容不同（不同类型的产品、改挂基产品、必须取值被改名等另行判为无效）；
   - **未变化**：内容完全一致；
   - **无效**：缺少必填值、平台 / 基产品 / 产品 / 集合 / 值类型 / 角色不存在、字段键重复、产品字段在基产品中没有对应字段、校验表达式编译失败、规则码跨集合重复等，面板逐条给出原因；
   面板顶部显示四类计数，分组列出「表 / 业务键 / 说明」，`未变化` 组仅列出前 30 行。
2. **执行**：面板内选择导入方式后点「开始导入」——
   - **合并 · 冲突覆盖**（默认）：写入新增项，并用文件内容覆盖冲突项；
   - **合并 · 冲突跳过**：只写入新增项，冲突项保留现状（面板列出被保留的键）；
   - **全量还原**：先清空该范围现有定义再写入（会二次确认）；元数据还原会**保留应用依赖的必须取值**（`VALUE_TYPE` 的 7 个类型、`FIELD_ROLE` 的 `BUSINESS` / `MANAGED`），避免还原后无法导入；
   - 无效项一律不写入，其余照常导入；导入完成后统一重算基产品与产品的 `schema_hash`，并写一条审计（动作 `IMPORT`）。

接口：`GET /api/definitions/export?scope=PRODUCT|META&format=xlsx|sql`、
`POST /api/definitions/import/preview?scope=…`（multipart `file`）、
`POST /api/definitions/import/{planId}`（`{"mode":"MERGE_OVERWRITE"|"MERGE_SKIP"|"FULL_RESTORE"}`）、
`DELETE /api/definitions/import/{planId}`（放弃预检）。预览结果在服务端保留 30 分钟。

## 字段值校验规则

在「元数据」里新建**集合类型 = 字段值校验规则**（`VALIDATION`）的集合，每个取值就是一条规则：

- **规则码**（枚举值代码）供字段表达式引用，跨所有 `VALIDATION` 集合唯一；
- **规则类型**为「正则表达式（Java）」或「通配符（`*` / `?`）」；
- **严重级别**为「警告（仅提示）」或「错误（阻断导入）」，默认警告；同一字段的表达式命中多条规则而失败时，
  取最严重的一级（只要有一条「错误」规则不通过，该行即被判定为阻断）；
- **表达式**即规则文本，保存时服务端编译校验，非法表达式直接拒绝（前端在表达式的状态行与保存按钮上同步反馈）；
- **表达式限制**：长度不超过 300 字符；不允许「在已含无界量词（`*` / `+` / `{m,}`）的分组上再加重词」的写法，
  例如 `(.*a){14}`、`(a+)+`、`(\w+\s?)*` 都会被拒绝并提示改写 —— 这类嵌套量词会让匹配时间指数增长，
  一条规则就能把一次导入拖成几小时；
- **即时测试**：输入一段文本点「测试」，显示是否匹配（`value` 也可以是公式或任意文本）；样本文本上限 4000 字符，
  超出时返回「长度超限」提示而不是执行匹配。

字段绑定发生在字段定义上（基产品字段与派生产品字段）：

- 字段编辑器底部有「校验规则表达式」，规则码以胶囊按钮列出，点一下即插入；表达式支持 `AND` / `OR` / `NOT`
  与括号，例如 `CCY_ISO AND NOT CCY_NUMERIC`（关键字大小写不敏感，规则码统一大写），因此**一个字段可以关联多条规则**；
- 表达式也会做语法与规则存在性校验（未知规则码返回 400），并可即时测试；
- 派生产品**继承**基产品的表达式并在基产品变更时跟随更新；在派生产品字段里改成别的表达式即为**覆盖**（提示「已覆盖基产品表达式」），
  清空则恢复继承；
- 规则被字段引用时，删除规则或整个集合返回 `409`；规则被停用后，引用它的字段按「无规则」处理（不会因此全部失败）。

校验语义：

- 校验对象是**导入时的原始单元格文本**（编辑后为用户输入的文本；不去空格、不做数值/日期归一）；
- `REGEX` 与通配符都是**全匹配**：`\d{3}` 只接受三位数字，需要部分匹配请自行加 `.*`；
- **默认区分大小写、跳过空值**：空值属于字段「必填」的职责，规则不会把空单元格判为失败；结果面板上的两个开关可以按需改变本次运行：
  - **忽略大小写**（默认不启用）：规则按不区分大小写匹配；
  - **不校验空值**（默认启用）：取消勾选后空白值也会交给规则判断；
  - 勾选开关后点面板上的**刷新**才会重新校验，结果与统计一并刷新；当前生效的开关同时以 chip 显示；
- 导入预览与导入提交固定**跳过空值、区分大小写**；
- **严重级别决定是否阻断导入**：警告级失败只是提示（预览单元格标黄并追加一条 `VALIDATION_FAILED` 警告，
  行仍可导入）；错误级失败会让该行在导入时被拒绝（预览单元格标红、行标记为无效，按「错误行前停止」策略决定是否继续）。
  用例/批次校验面板始终只是列出问题、不改数据，但会用颜色与 chip 区分「警告」「阻断」；
- 结果面板同时列出**没有校验规则的字段**，避免「全部通过」被误解为「已全部覆盖」；值类型引用了集合的字段
  由类型层校验，算作已覆盖（面板以「集合」chip 标注 `SET:<集合码>`），不计入「无规则字段」。

入口：导入向导（预览单元格标红）、批次详情（用例行校验图标 = 单例校验，工具栏「校验」= 整批校验）、
批次浏览（用例侧栏导航按钮右侧的批量校验按钮、主表「批次详情」右侧的「校验」按钮）。

### 值类型与校验规则如何分工

两者是**分层**关系，不冲突，表达力有重叠但职责不同：

| 维度 | 值类型（VALUE_TYPE） | 字段值校验规则（VALIDATION） |
| --- | --- | --- |
| 作用层级 | 字段的**结构**：能不能按该类型解析 | 字段的**业务规则**：值是否符合约定 |
| 判定时机 | 导入解析（预览与提交）时按类型解析并归一化 | 解析成功后按原始文本匹配表达式 |
| 失败级别 | 固定为**错误**，该行不导入 | 由规则的**严重级别**决定（警告 / 错误） |
| 可复用性 | 一个类型可被多个字段共用 | 一条规则可被多个字段的表达式共用（支持 `AND` / `OR` / `NOT`） |
| 覆盖范围 | 单个字段 | 单个字段，且一条表达式可组合多条规则 |

- 枚举型值类型（引用集合的值类型，如 `CONV_METHOD`）本身已经约束了取值集合，因此**视为已定义规则**：
  校验面板把它算作已覆盖字段（显示 `SET:<集合码>`），不再列入「无规则字段」；它不会参与表达式判定，避免同一约束重复报错。
- 需要「范围 / 长度 / 格式 / 枚举之外的条件」时用校验规则；需要「结构性类型（数值、日期、布尔）」时用值类型。
- 同一字段可以两者都有：先按类型解析（类型不符 → 错误、该行不导入），再用原始文本匹配规则（规则不符 → 按严重级别处理）。

## 原始文本与「类型」

字段的**类型**只用于**显示格式提示、筛选与编辑控件**，不参与业务处理：

- 导入时把单元格**原始文本**（不去空格、不转换格式）存进 `raw_json`（`{"data":{字段Key:原文},"managed":{存储键:原文}}`），
  **原文是所有展示与业务处理的唯一取值来源**。
- 为节省空间，只有**日期、时间、日期时间、布尔、数值**类型额外保存一份归一化副本（`data_json`：`LocalDate` /
  `LocalTime` / `LocalDateTime` / `Boolean` / `BigDecimal`），**仅供排序、搜索、筛选内部使用**；
  文本与枚举类型不保存任何副本，只保留原文。
- **展示一律使用原文**（所见即所得）：用例列表的预览列、用例详情、纵向浏览、导入预览、导出 CSV、导出记录的数据展示，
  全部输出原始单元格文本。例如单元格写 `1,500,000.00`、`2026/01/05`、`y`、`  IRS-9001  `，界面与导出就是这些文本。
- **业务处理同样使用原文**：字段值校验、用例对比、批次对比、三种记录 ID。
- **编辑写入原文**：单条保存、批量更新字段、导出前的临时覆盖都把**用户提交的字符串**作为该字段的新原文（前后空格、千分位、原始日期写法都保留），
  并同步刷新归一化副本（仅日期 / 时间 / 日期时间 / 布尔 / 数值类型）；清空字段时原文与副本一并删除，公式更新不改变原文。
  因此「改一次值 → 展示、校验、对比、记录 ID、导出」始终看到同一份文本。
- 导入预览阶段仍按类型解析：无法按类型解析的值按**错误**记录并阻断该行（与之前一致），但不影响已入库数据。
- 历史数据（本次升级前导入的行）没有原文，展示按归一值回退，行为与升级前一致；重新导入的行则始终使用原文。

## 关键规则

1. **列映射只看列名**：列名去除首尾空格、忽略大小写后与产品字段的列名**完全相等**才算命中；别名、标点、
   内部空格差异一律不匹配，也不做任何相似度猜测。归类规则：
   - **严格模式**按位置比较定义区（第 k 列 ↔ 第 k 个字段，含管理字段），因此允许重名列，但定义区宽度必须等于字段数；
     定义区之外的列一律是**未映射列**。
   - **非严格模式**业务字段按列名匹配（自「定义起始列号」起）、已声明的管理字段按列名在整个表头匹配，
     其余列是**未映射列**；文件列名重复时只映射首次出现的那一列。
2. **重复列名只在严格模式合法**：非严格模式下产品字段列名重复 → 产品定义无效（列表状态显示「无效」、
   导入被 `PRODUCT_DEFINITION_INVALID` 拦截）；文件侧重复列名 → `DUPLICATE_SOURCE_HEADER` **警告**，
   仅首个同名列参与映射，其余留作未映射列。严格模式下列名重复不算错误，仅提示 `DUPLICATE_HEADER_MAPPING` 并按位置匹配。
3. **未映射列**：不参与映射的列进入 `extras`（不静默丢弃），每条给一条 `UNMAPPED_TRADE_COLUMN` 警告；
   非严格模式下若未映射列夹在交易列之间，另给一条 `TRADE_BLOCK_NOT_CONTIGUOUS` 警告（严格模式下则是错误）。
4. **四套 ID**：
   - Test Case Id：文件中 `_TestCaseId`，缺失则生成 `TC-{businessId[0..12]}`；
   - Original Record Id：`sha256(文件名|sheet|行号)[0..31]`；
   - Business Record Id：`sha256(产品定义全部字段的取值)`，管理列（`_TestCaseId`、`_Remarks`）的取值也参与，公式字段用**公式文本**参与哈希；
   - Core Business Record Id：同上算法，但**只取业务（交易）字段**，管理列不参与——用于判断「交易内容是否相同」。
   所有取值按**原始文本**逐字符参与哈希（导入时的单元格原文，编辑后为用户输入的文本；不去空格、不做数值/日期归一，`1000` 与 `1,000.00` 不同）；三者在用例列表中均完整显示 32 位（悬停列头可查看定义与计算方式），后两者在本批次内重复时会行内标记。
5. **公式**：导入时把工作簿复制一份不可变基线（`batches/{batchId}/source.xlsx`，读取前校验 `sha256`），
   公式文本按原文存 `formula_json`（只在计算 Business Record Id 时可选地掩码行号），UI 显示 `ƒ` 徽标。
   导出前默认用基线 + 当前用例值重算公式，CSV 输出重算后的值而不是源文件的缓存值；不支持求值的公式
   保留用例值并告警。
6. **管理列**：只有产品定义中声明为 `MANAGED` 的字段才算管理列，写入 `managed_json`
   （`_TestCaseId` 落到独立列）。没有声明的列（包括文件里的 `_TestCaseId` / `_Remarks`）都是**未映射列**，
   进入 `extras`；要保留它们，就在产品定义里声明为管理字段。
   出厂种子中 `MW/IRS`（27 个字段）与 `MW/OIS`（22 个字段）都声明了 `_TestCaseId`、`_Remarks`，`MW/CCSIRS` 额外声明了
   `Scenario Group`、`Priority`（合计 70 个字段）。`MW/IRS` 的 `Report Timestamp` 是业务字段（交易块首列、恒必填），
   Excel 中的时间单元格按原样保存为文本，例如 `2026-11-09T22:53:51.79`；样例 `IRS.Standard` 中
   `Report Timestamp` 与 `Trade Date` 使用 `=NOW()` / `=TODAY()`，用于验证公式保存与导出重算。
7. **产出隔离**：产出用例 `origin=EXTERNAL_OUTPUT`，只在 `/outputs` 出现（外部工具派发链路已按需求移除，该页保留用于浏览历史产出）。
8. **删除语义**：**任务与用例是硬删**（物理 `DELETE`，不可恢复）——删除任务会一并清除其批次（含克隆批次与
   已单独删除的批次）、这些批次下的全部用例、这些批次的导出记录与归档 CSV，并断开其它模块遗留的引用
   （`external_job_case` 行、`external_output.imported_batch_id`）；文件层面删除该批次的**工作簿基线目录**
   `batches/{batchId}` 与原上传文件（仅当**没有其它批次**仍引用该上传时才删），并清掉预览内存缓存；
   删除用例会清除该行与 `cloned_from` / `external_job_case` 等指向它的引用。
   批次删除仍为软删（`status=DELETED`，其用例随之软删），删除任务时会把它们一并物理清除。
9. **读取上限与防护**：单文件 50MB、单 sheet 20 万行、最多 50 个 sheet；另限
   **单行最多 1000 列**（`app.limits.max-columns`）与**单元格最多 32768 字符**（`app.limits.max-cell-length`），
   超出即返回 400 并指出行列位置。xlsx 额外限制解压后的单条目与共享字符串大小（防 zip bomb）。
   CSV 预览**流式解析**：只把前若干行读进内存，总行数照样准确统计；导入提交时才整表读取。
   预览**翻页**同样只读窗口（`POST /api/uploads/{id}/preview/rows` 的 `sampleOffset` / `sampleLimit`），
   任何页码都按需读取，页面不会因为文件变大而变慢。
10. **批量更新范围必须显式**：`caseIds`（选中）或 `query` / `hasFormula`（筛选）都没有时，必须显式声明
   `scope=BATCH`，否则 400 —— 字段名写错也不会静默改写整批。
11. **临时文件回收**：导出等写盘操作先写 `*.tmp` 再改名；失败时立即删除，另有定时任务清理超过 1 小时的
   残留 `*.tmp`（每 6 小时一次）。
12. **导入是单个事务**：任务入库即 `RUNNING`，提交时一次写成 `SUCCEEDED` / `PARTIAL` / `FAILED`，
   外部永远看不到「排队 / 进行中」的中间态（因此状态卡片没有「待处理」）；并入已有任务时只累加计数，
   并把状态重新落定为最终值（本次有失败或无效行 → `PARTIAL`，仍无任何批次 → `FAILED`），不会把任务留在 `RUNNING`。

## 与开发计划的偏差（已确认）

| 偏差 | 原因 |
| --- | --- |
| Flyway 用 `spring-boot-starter-flyway` | Boot 4 把 Flyway 自动配置拆到独立模块，仅 `flyway-core` 不会迁移 |
| H2 JDBC URL 不带 `AUTO_SERVER` | H2 2.4 不支持 `AUTO_SERVER=TRUE` 与 `DB_CLOSE_ON_EXIT=FALSE` 组合；单实例无需多进程访问 |
| `app.import.*` 通过 `@Name("import")` 绑定 | `import` 是 Java 关键字，字段名用 `importRules` |
| 数据目录用 JVM 参数/环境变量 | 数据目录决定 JDBC URL，需在上下文启动前确定 |
| Jackson 浮点反序列化为 `BigDecimal` | 保证 `1,500,000.00` 这类金额按原精度导出（`spring.jackson.deserialization.use-big-decimal-for-floats`） |
| 前端为服务端页面壳 + 客户端渲染 | 与参考项目一致的纯 ES Module 方式；无 npm 构建 |
| CSV 读写用 Commons CSV 1.14.1（计划 §6）而非 `jackson-data-format-csv` | 计划明确要求 Commons CSV，且需要按位置输出重名列、自定义引号策略（自研 `CsvWriter`） |
| 外部「批量导入工具」派发链路已移除 | 按需求删除 `external-jobs` 页面、外部任务 API 与回调/扫描服务，待后续重新设计；`/outputs` 保留用于浏览历史产出 |

更多决策见 [docs/ADR-0001-外部任务与文件布局.md](./docs/ADR-0001-外部任务与文件布局.md)。
